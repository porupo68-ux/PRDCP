1. What happened

After Cycle 013 completed Deliberation and persisted its Conclusion outbox, the localized CLI command `--conclusion` stopped immediately with `Deliberation Result is not Conclusion-ready`. No Conclusion state was created and no Conclusion Provider call occurred.

The persisted Quality Review is approved_with_conditions, has no blocking finding IDs, and reports conclusion_readiness=ready_with_conditions. That is the exact lowercase value required by the Deliberation Quality Reviewer RD.

2. Root cause

The same inter-layer field had three conflicting contracts:

- Deliberation Quality Reviewer RD: lowercase ready / ready_with_conditions / not_ready / undetermined
- Deliberation Pydantic schema: unconstrained string
- Conclusion handoff validator and Mock fixture: uppercase READY / READY_WITH_CONDITIONS / NOT_READY

Because the schema was only `str`, OpenRouter was free to follow the RD. Because Mock emitted uppercase, regression tests exercised only the receiver's accidental uppercase convention. The real response was valid according to the RD but rejected by Conclusion.

This is not an Evidence shortage, Provider failure, or bad Quality Review decision. It is a cross-layer type contract failure.

10. Design meaning

A cross-layer readiness flag is a protocol type, not presentation text. The producing RD, provider-visible schema, Mock, persisted artifact, and receiving Manager must share one canonical representation. Compatibility belongs at the read boundary and must not redefine the generation contract. When a PMP payload duplicates an artifact for convenience, both copies must agree or the receiver cannot know which one is authoritative.
