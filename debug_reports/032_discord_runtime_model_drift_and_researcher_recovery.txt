1. What happened

Producer completed normally. Researcher then created nine initial Research Tasks, but all
nine Structured Reasoning calls failed. The persisted ERROR PMP records identify
perplexity/sonar or perplexity/sonar-deep-research and HTTP 404
ProviderCapabilityError: no endpoint accepted the required parameters.

At investigation time, Settings.from_env() configured every Researcher specialist as
google/gemini-3.7-flash. The discrepancy was real: the long-lived Discord process had
constructed its managers and registries before the model configuration changed and kept
the old Agent.model values.

2. Root cause

There were two runtime-configuration defects.

* Discord constructed all five managers once and never compared their live registry
  models with the current configuration before a later command.
* The local .env loader used os.environ.setdefault(). Re-reading Settings in the same
  process therefore could not observe a changed .env value that the loader itself had
  installed earlier.

The Researcher failure also exposes a second, independent recovery precondition. The
production workflow contains no Researcher Retrieval Context for any of the nine tasks.
The only retrieval_context and retrieval reservation in this workflow belong to the
Producer General Opinion Analyst from Cycle 031. This indicates that the old Discord
runtime predated, or otherwise did not execute, the Cycle 029 Retrieval -> Structured
Reasoning separation for Researcher. A model-only retry cannot reconstruct evidence
without performing a new search.

3. Why Doctor previously reported READY

Doctor inspected a newly created Settings object and current OpenRouter metadata. It did
not receive the already-running Discord managers, so it could prove that the configured
models were compatible but could not prove that the live registries held those models.
Configured compatibility and runtime identity are now separate checks.

Definitions used by Cycle 032:

* Configured Model: current Settings/.env model for an agent.
* Runtime Model: model held by the live manager registry (Agent.model, or the manager
  model snapshot held by registry.models).
* Resolved Model: a verified provider-agent-output-schema compatibility binding used at
  invocation time. It is reported separately and is not mistaken for base-model drift.

5. Changes made

Runtime drift control:

* Added a 31-agent runtime audit that reads live registries, current configured models,
  and verified compatibility bindings as separate values.
* Added a Discord execution-boundary guard for Producer, Researcher, Deliberation,
  Conclusion, Playwright, resume/integration commands, and automatic layer transitions.
  Drift raises RUNTIME_MODEL_DRIFT before provider reservation or provider invocation.
* Added !runtime_models [layer]. It reports a compact current count and full details only
  for drifted agents.
* Added immutable audit artifacts under runtime_model_snapshots without modifying workflow
  JSON/PMP schemas.
* Changed .env refresh so only values previously installed by the loader may be refreshed;
  parent-process/operator-owned environment values retain precedence.
* Kept verified compatibility bindings out of the drift predicate, preventing false drift
  for Conclusion Position Generator and Playwright Visual Director repairs.

Researcher recovery:

* Added --researcher-runtime-model-repair WORKFLOW_ID.
* Recovery accepts only an incomplete initial task with a correlated original TASK and
  HTTP 404 capability ERROR, a different current runtime model, COMPATIBLE capability
  metadata, an original provider reservation, and an exact saved Retrieval Context/hash.
* Every call uses <original_task_id>_runtime_model_repair_1.
* Added persistent PENDING -> CONSUMED one-shot authorization bound to workflow, agent,
  old/new model, error PMP, retrieval ID, retrieval hash, and repair reservation.
* Recovery is sequential. A validated RESULT/PMP is persisted before the next task is
  authorized. Saved results are reconciled before every paid call.
* Automatic provider retry is zero in required Demo Safe Mode. A consumed repair cannot
  be repaired again.
* Missing Retrieval fails closed before authorization, search, reservation, or reasoning.
* Cycle 030 source hydration and unknown-source rejection remain active for all seven
  Researcher specialists.

Reservation boundary hardening discovered by full regression:

Directly constructed managers under the long Work path exposed a common Windows path
length failure in the old global fallback reservation directory. All five managers now
use this precedence: explicit Provider reservation root, then PRDCP_DATA_DIR, then the
manager Repository data directory. Production builders already supplied the explicit
root, so production reservation locations do not change.

9. Design meaning and recurrence prevention

Configuration compatibility is no longer treated as proof of live runtime identity.
Provider execution now has an explicit runtime boundary: the live model must equal the
current configured base model before a reservation exists. Compatibility bindings remain
audited invocation-time resolutions.

Recovery is not a general retry. It is an evidence-bound transition from one immutable
failed identity to one immutable repair identity. Retrieval evidence is a required
checkpoint, not something recovery silently recreates. This prevents old-provider replay,
unplanned searches, duplicate billing, and repair-of-repair loops.
