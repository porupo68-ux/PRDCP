What happened
Cycle 028 proved that nine Perplexity-bound agents did not satisfy the strict Structured Output capability preflight. The deeper design problem was that PRDCP expected one model call to perform search, source acquisition, reasoning, and strict JSON generation. Replacing the model names alone would either lose search or preserve the same hidden coupling.

Root cause
StructuredAgent had only one canonical input path. ResearchTask was serialized once for budget preflight and serialized again inside run(), with no durable retrieval boundary. Search results therefore had no separate identity, checkpoint, reservation, failure class, or recovery path. ResearchResult could also return source identities that were not members of any application-owned retrieved set.

Design correction
1. StructuredAgent now has an async prepare_provider_input() hook. Its default is an exact no-op.
2. The prepared dictionary is computed once and used unchanged by budget preflight and the actual Provider call.
3. Research Planner remains retrieval-free because its RD and prompt explicitly prohibit evidence collection.
4. General Opinion Analyst receives a lightweight retrieval view. Seven Researcher specialists receive strategy-specific evidence retrieval views.
5. Canonical PMP payloads and ResearchTask objects are never extended or rewritten. retrieval_context is a runtime-only Provider view.
6. Retrieval has provider-neutral models, a replaceable provider protocol, Mock and OpenRouter Web Search adapters, deterministic retrieval/source identities, separate reservations, and durable contexts.
7. Retrieval is persisted before the LLM reservation/call. An LLM operator-retry identity maps back to the original retrieval identity, so the search call count remains zero during LLM recovery.
8. A reservation without a context is classified as ambiguous and blocks automatic duplicate retrieval.
9. ResearchResult strict schemas bind source_id, URL, title, and excerpt to retrieved values. Local validation also checks source pairing and grounded identity metadata. General Opinion URLs and labels are similarly bounded.
10. Doctor reports the 31 Reasoning models and eight retrieval-required agents as separate capability dimensions.

Search provider decision
The OpenRouter openrouter:web_search server tool was selected behind a provider adapter. It exposes URL citation annotations containing URL, title, and excerpt while allowing the later PRDCP Structured Output call to remain independent. PRDCP forces the search tool for the retrieval request, caps total results, persists citations, then performs structured reasoning in a separate call. The adapter remains replaceable; no agent imports OpenRouter transport details.

Failure-mode audit
- Default agents accidentally receiving retrieval: prevented by opt-in hook overrides and a ResearchTask schema guard.
- Researcher Quality Reviewer sharing ResearcherAgent: explicitly remains retrieval-free.
- Preflight/actual input mismatch: one prepared object is reused for both.
- Search success followed by LLM failure: persisted context is reused.
- Search failure followed by retry: reservation blocks an automatic duplicate.
- Revision and external Researcher Return: revision task identity creates a new retrieval identity; existing evidence remains in the report.
- Provider retry/contract repair/capability repair: suffixes reuse the original retrieval identity.
- Hallucinated URL/source/title/excerpt: Provider schema and local contract reject values outside retrieval context.
- General Opinion with fewer than three retrieved sources: LLM call is blocked as RETRIEVAL_NO_RESULTS instead of inventing sources.
- Safe Mode loophole: search reservations are independent and one-shot, including when LLM Safe Mode would otherwise allow a call.
- Downstream regressions: Producer, Researcher, Deliberation, Conclusion, and Playwright all passed the full verification suite.

System-design meaning
Search is now an explicit, durable source-acquisition subsystem instead of an undocumented property of a selected LLM. Reasoning models can be selected for strict JSON reliability, while Search Providers can be selected for source quality and cost. Recovery can reuse acquired evidence without duplicate external calls, and downstream traceability begins at an application-owned retrieval source identity.

Prevention
The new tests fail if a future change mutates canonical payloads, prepares different preflight and send inputs, retries retrieval after an ambiguous failure, lets retrieval-free agents search, or accepts a ResearchResult source outside its retrieval context. Doctor blocks a Real workflow unless both Reasoning and Retrieval capability dimensions are ready.
