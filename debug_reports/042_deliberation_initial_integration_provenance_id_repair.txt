1. What happened

The saved Deliberation failed while validating the paid Initial Integration response.
InitialIntegratedAnalysis.stakeholder_structure.source_analysis_id contained an
integration_initial_* value. That field represents the source analysis artifact,
so the existing Pydantic validator correctly rejected the integration artifact ID.

The three primary analyst Provider responses were already present in PMP history.
Argument and Causal were accepted into state. Stakeholder had also completed, but
its response used a non-canonical source alias for one specific fact and was
temporarily excluded before the Manager invocation. The Manager was therefore
called with Argument and Causal only, and its invalid response was persisted.

2. Root cause

The application model enforced analysis prefixes with a Pydantic field validator,
but that semantic validator is not represented in the JSON Schema sent to the LLM.
The Provider-visible source_analysis_id field was only a generic string. The
Deliberation Manager prompt also embedded the unspecialized root schema. Thus the
model could invent integration_initial_* as stakeholder provenance even though
local validation correctly rejected it.

A prefix check alone is insufficient: causal_analysis_* is syntactically an
analysis ID but is still the wrong owner for stakeholder_structure. The previous
Manager boundary did not cross-check the exact IDs in the request by role.

3. Design meaning of the repair

source_analysis_id now means exactly one thing: the role-owned analysis artifact
that was present in the same Manager request. integration_id continues to identify
the integration artifact itself. If a primary role is absent under the existing
two-of-three continuation rule, deliberation.manager remains the explicit owner of
the Manager-synthesized section. These meanings are not interchangeable.

The saved invalid Manager payload is not repaired by replacing only its ID. The
original Manager request did not contain the recovered Stakeholder analysis, so
post-hoc rebinding would falsely claim provenance. Recovery first restores the
saved Stakeholder result without a Provider call, then regenerates Initial
Integration under the distinct existing contract_repair_1 task identity with all
three analysis artifacts present.

4. Code changes

- Deliberation Initial and Final Integration strict schemas are specialized per
  request. IntegratedClaim, CausalStructure, StakeholderStructure,
  ProblemDefinition, Agreement/Conflict references, and Traceability analysis IDs
  receive compact exact-ID allowlists.
- The Deliberation Manager prompt now receives the same specialized schema as the
  OpenRouter response_format boundary.
- The Manager performs exact role-ownership validation after Pydantic validation.
  A valid-prefix/wrong-role payload is persisted as a contract failure and cannot
  silently enter a checkpoint.
- Saved Manager payload recovery applies the same exact ownership check. It never
  invents provenance for an artifact absent from the original generation.
- Legacy mock-shape adapters preserve explicitly supplied provenance IDs.
- The Deliberation mock fixture emits all authoritative primary IDs and preserves
  them through Final Integration.
- Added production-state clone verification script:
  scripts/verify_cycle042_provenance_clone.py.

11. Prevention

Every future ID contract change must be verified at all of these boundaries:
  canonical owner -> generator -> provider schema -> local semantic validation ->
  persistence -> reload -> direct reviewer -> revision -> downstream handoff ->
  Delivery.

The key rule is: source_*_id identifies the referenced artifact, not the artifact
currently being created.
