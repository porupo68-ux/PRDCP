1. What happened

The explicit one-time Real retry from Cycle 015 reached OpenRouter and reused all saved upstream checkpoints, but the configured Qwen3.5 Flash Position Generator again returned one large numeric value instead of the required JSON object. The strict response boundary rejected it. The retry authorization and retry reservation were consumed exactly once; no Evaluation, Integration, Quality Review, or upstream Provider call ran.

2. Failure location

The response failed at `providers/openrouter_provider.py`, after a successful HTTP response envelope but before Pydantic validation. The saved Error PMP identifies the requested model, SHA-256 hash, character length 8224, root type `float`, and invalid path `$`. No response body is stored.

4. Root cause

There are two distinct causes. First, PRDCP sent `response_format` but did not set OpenRouter `provider.require_parameters=true`. OpenRouter documents that this routing preference defaults to false; without it, parameter support was not a hard routing condition. This is a systemic request-contract defect affecting all 22 Structured Output roots.

Second, this exact Qwen model/endpoint produced a non-object response twice. OpenRouter currently advertises Structured Output support for compatible endpoints, but also documents that strict enforcement varies by provider and is not guaranteed identically on every endpoint. Because the same model failed both the original call and the only allowed retry, another send under the same task/model is no longer a retryable transient operation. It is a provider-contract compatibility failure requiring a different model and a distinct logical task.

5. Why the problem occurred

The code enforced schema shape and response decoding, but it did not express endpoint parameter support as a routing invariant. The existing one-shot retry correctly prevented accidental duplicate billing, yet there was no audited way to change the model after two correlated contract-invalid responses. Manually editing a reservation, deleting storage, or retrying the retry would violate PRDCP idempotency.

6. Why prior tests did not detect it

Mock providers always return valid schema objects and do not simulate OpenRouter endpoint selection. The schema audit verified JSON Schema compatibility, not the `provider` routing object in the HTTP request. Cycle 015 added response-boundary failures, but its fault provider recovered on the same model after one injected failure and therefore did not model repeated model-specific noncompliance.

7. Repair plan

1. Require all OpenRouter requests to route only to endpoints supporting every supplied parameter.
2. Preserve the original task, retry task, reservations, errors, and authorization.
3. Permit a provider-contract repair only after both original and one-shot retry are correlated contract-invalid responses.
4. Require an explicitly different, syntactically valid model ID.
5. Use a deterministic `_provider_contract_repair_1` task, dedicated PENDING/CONSUMED authorization, and separate reservation.
6. Reuse valid checkpoints and rerun only the failed Conclusion stage plus its true downstream dependencies.
7. Block a fourth call if the repair itself fails.

8. Implemented repair

- Every `OpenRouterModelProvider.generate_structured` request now sends `provider: {require_parameters: true}`.
- Added a shared persistent ProviderContractRepairAuthorizationStore.
- Shared StructuredAgent execution supports an explicit model override without mutating the registered Agent model and validates/consumes repair authorization at reservation time.

10. Design meaning

Structured Output is now a routing precondition, not merely a request hint. A same-task retry remains limited to one explicit operation. After repeated contract failure, changing models is represented as a new auditable logical operation instead of erasing history or pretending the retry never happened. This separates transient transport recovery from provider/model contract repair and keeps billing/idempotency reasoning inspectable.

11. Other-layer impact

The `require_parameters` guard and model-override-safe StructuredAgent path are shared by Producer, Researcher, Deliberation, Conclusion, and Playwright. Existing task IDs and normal Agent models do not change. Existing Researcher/Deliberation retry paths remain unchanged. The new contract-repair CLI is scoped to Conclusion because that is the observed failed checkpoint; no other layer receives an automatic model fallback.

12. Same-family Failure Mode audit

- All 22 roots retain recursive strict JSON Schema and finite-object response validation.
