2. Root cause

Cycle 036 removed the redundant source_name and author_or_organization fields from the
Provider schema, but their value still came from the Provider-generated typed identity,
GovernmentMetadata.organization. Gemini merged the official cas.go.jp publisher identity
with a document organization into one new string. That string does not occur in the saved
title, URL or PDF text and is not an official-domain alias, so the deterministic validator
correctly rejected it.

The remaining design error was ownership. Source identity is provenance. The saved
Retrieval Context, not the reasoning model, owns provenance. Hydrating two aliases from a
third generated spelling reduced duplication but did not eliminate generative ownership.

The same boundary existed in all seven Researcher types: expert_name/affiliation,
journal_name, organization/country, media_name, platform, politician_name/party/position
and organization_name could still be generated even though Retrieval did not contain
separate authoritative provenance columns.

3. Why Mock and Doctor did not detect it

Cycle 036 Mock fixtures generated one deliberately grounded primary identity and then
verified alias hydration. They did not inject a Provider-generated concatenation into the
remaining primary field. Doctor checks configuration, RD and model capabilities; it
cannot prove ownership of semantic fields inside an otherwise valid schema.

Cycle 037 adds schema-level assertions and hydration Fault Injection for all seven source
types, including a cross-category case where an Academic source is hosted on
copyright.gov. Production-clone Fault Injection initially found that a government-friendly
domain label was being applied to this Academic source. The repair now limits friendly
official labels to GOVERNMENT; other categories use the exact saved hostname.

4. Repair design

All Provider-bound ResearchResult schemas now remove Retrieval-owned top-level fields:

* title, source_name, URL and author_or_organization;
* published_at, retrieved_at and relevant_excerpt.

They also remove type-specific provenance fields:

* EXPERT: expert_name, affiliation;
* ACADEMIC: journal_name;
* GOVERNMENT: organization, country;
* NEWS: media_name;
* PUBLIC_OPINION: platform;
* POLITICIAN: politician_name, party, position;
* INDUSTRY: organization_name.

The Provider still selects a saved source_id and produces analytical fields. Before
Pydantic and local contract validation, the shared Researcher adapter restores immutable
fields and provenance from the selected saved source.

GOVERNMENT sources may receive a friendly organization label only from a closed official
hostname mapping. Other categories use the exact normalized hostname, which is directly
present in the immutable URL. Country is derived only from a closed country-code domain
mapping. EXPERT and POLITICIAN person/affiliation values are None when the saved Context
cannot establish them without inference. Existing persisted strings remain readable;
existing workflow JSON is not migrated or overwritten.

The post-hydration validator remains active. Tampering a hydrated organization or country
to an ungrounded value is still rejected. The repair therefore removes hallucination
opportunity without weakening evidence grounding.
