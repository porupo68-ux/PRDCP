Cycle 041 — Researcher Repair Contract Synchronization and Discord Failure Closure
Date: 2026-08-18 JST
Production workflow: 4b837e0e-9e1c-4150-97e1-ac31ef87024e

1. What happened

Cycle 040 correctly persisted two zero-call Research Report repair artifacts. One of
them used the new repair_kind report_limitation_exact_deduplication. Researcher state,
the Human Evidence Decision, and the Deliberation outbox all contained that valid
artifact. Deliberation, however, still treated the older official-industry source
reclassification shape as the only HumanEvidenceIntegrityRepair contract. The saved
Researcher handoff therefore failed before Deliberation could create a workflow.

The same exception escaped the Discord command path after the status channel had
already shown RUNNING. Discord then attempted to send the complete validation error
and traceback. A sufficiently long exception exceeded Discord's 2000-character
message limit, causing a second notification failure and leaving the operational
status at RUNNING.

2. Why it happened

The shared contract did not have one canonical validation owner. Researcher had
introduced ResearchReportIntegrityRepair, while the direct Deliberation consumer
still performed local validation against the legacy class. Producer, persistence,
and consumer had therefore drifted even though each individual model was valid.

Discord execution commands also caught only selected exception types. The global
handler re-raised other failures, and exception text was sent without an operational
size limit. State/status failure closure was consequently dependent on which Python
exception class happened to cross the command boundary.

3. How it was fixed

- researcher.schemas.human_evidence now owns one canonical discriminated union for:
  - official_industry_source_reclassification
  - recognized_media_source_reclassification
  - report_limitation_exact_deduplication
- The canonical module owns the TypeAdapter and public validation function.
  Deliberation imports that validator instead of rebuilding or narrowing the union.
- ResearcherWorkflowState persistence and DeliberationResearchContext both use the
  same union. Unknown repair_kind values fail closed; malformed known variants also
  fail closed with an artifact validation error.
- The union is declared after both concrete models, removing the consumer-visible
  forward-reference dependency.
- Discord now emits a single-line operational summary capped at 700 characters.
  Complete exception and traceback information is retained in application logs.
- Every Researcher, Deliberation, Conclusion, and Playwright execution path, including
  automatic layer chaining, catches execution failures through one helper. That helper
  sends the bounded summary and always routes the layer status to ERROR. The route
  update itself is protected so a notification failure cannot hide the original fault.
- Non-execution Discord commands also use bounded summaries; direct ctx.send(str(exc))
  and the old re-raise path were removed.

4. Design meaning

The repair artifact is now a versioned, discriminated event contract instead of an
implementation-specific Researcher class. Adding a new repair variant requires a
change at the canonical owner and is then validated consistently during state load,
outbox reload, and direct downstream consumption. The system does not silently coerce
unknown repairs and does not regenerate the saved Research Report.

Discord is now an operational projection of workflow execution rather than an
unbounded traceback transport. Logs preserve diagnostic fidelity, while the control
plane communicates a stable, bounded failure state. A handoff validation error cannot
leave the visible layer in RUNNING merely because the error message is large.

10. Prevention

- Shared persisted unions are validated only at their canonical schema owner.
- New repair kinds require persist/reload/direct-consumer regression coverage.
- The cross-layer production clone verifies transitive downstream and Delivery impact.
- Unknown discriminators fail closed before any Provider call.
- Discord exception text is bounded independently of diagnostic logging.
- Execution error handling always closes the visible layer status as ERROR.
- Read-only clone hashing and isolated reservations prevent validation from mutating
  production workflow data.
