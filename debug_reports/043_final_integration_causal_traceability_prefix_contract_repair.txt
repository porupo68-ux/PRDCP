1. What happened

The saved Deliberation reached Final Integration after all three primary analyses,
Initial Integration, and Counterargument completed. The paid Final Manager response
was received and persisted as an invalid payload, but local Pydantic validation
rejected two traceability references:

  alt_interp_task_fragmentation_and_busyness
  alt_interp_skill_ceiling_decay

Both appeared in FinalIntegratedAnalysis.traceability_index[*].causal_item_ids.
The existing validator allowed primary Causal Analyst namespaces only:
causal_, mechanism_, structure_/structural_, feedback_, alternative_, and alt_exp_.
The workflow therefore closed as FAILED rather than storing an invalid checkpoint.

2. Canonical ownership and alt_exp_ distinction

alt_exp_/alternative_ are owned by the Causal & Structural Analyst. They identify
primary competing causal explanations and are valid in the primary causal result,
Initial Integration, Final Integration, and downstream causal traceability.

alt_interp_ is owned by the Counterargument Analyst. It identifies an alternative
interpretation produced while challenging the Initial Integration. It is not valid
in the primary Causal Analyst result or Initial Integration.

Final Integration is the deliberate ownership transition. The Manager may promote
an exact Counterargument alt_interp_* artifact into
causal_structure.alternative_explanations when it retains the originating
counterargument in source_counterargument_ids. At that point it is a real item in
the final causal model and causal_item_ids must be able to trace it. The production
payload did exactly this for both rejected IDs. It was not a naming typo and must
not be renamed mechanically to alt_exp_*.

3. Root cause

The Counterargument producer and Final Manager were semantically consistent, but
the shared traceability consumer still represented only the pre-Counterargument
primary causal namespace. This was contract drift between a later producer stage
and FinalIntegratedAnalysis validation.

The same-family audit found two read-path variants of the same problem:

- canonicalize_legacy_causal_item_ids accepted alternative_* but incorrectly
  treated the equally canonical alt_exp_* namespace as legacy;
- saved Final recovery used startswith("alt_") broadly and would rename canonical
  alt_exp_* or alt_interp_* IDs while trying to repair old alt_1 placeholders.

Those paths did not cause the first failure, but would have changed valid IDs on
Recovery. They were corrected in the same Cycle because they share the exact
namespace-ownership failure mode.

4. Design meaning of the repair

The contract is stage-aware rather than globally permissive:

- Counterargument alternative_interpretations require alt_interp_* IDs.
- Primary causal alternatives remain alternative_*/alt_exp_* only.
- Initial Integration rejects alt_interp_* in both its causal model and trace.
- Final Integration accepts alt_interp_* only as a declared alternative
  explanation with source_counterargument_ids.
- A Final trace may reference an alt_interp_* ID only when the exact ID was present
  in the Counterargument artifact supplied to that Manager request.
- Unknown prefixes and valid-looking but non-source alt_interp_* IDs fail closed.

The Provider-visible schema now contains the bounded causal trace pattern. The
Initial request specialization excludes alt_interp_*; the Final request pattern
includes it. Local Pydantic and cross-artifact validation repeat the semantic
checks after the Provider response.

12. Prevention

Every future identifier-contract change must be audited in both directions:

  canonical owner -> producer -> Provider schema -> local validator -> persistence
  -> reload -> direct consumer -> transitive downstream -> Delivery

and:

  old consumer assumptions -> compatibility adapters -> recovery -> fault paths.

Prefix similarity is not semantic equivalence. A namespace may cross ownership
only at an explicit integration boundary with source lineage retained.
