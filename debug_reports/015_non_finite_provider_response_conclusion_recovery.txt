1. What happened

The localized Real Conclusion continuation passed Cycle 014's readiness boundary and made exactly one Position Generator call. OpenRouter returned message content that Python json.loads accepted as the float `inf`. PositionGenerationResult requires an object, so Pydantic stopped with input_value=inf, input_type=float. Conclusion became FAILED. Decision Evaluator, Decision Integrator, and Conclusion Quality Reviewer were not called. Automatic retry was zero and the original reservation remained.

2. Where it happened

Workflow 15f3f5c5-4167-447d-b255-069fc7f5beb2, conclusion.position_generator, logical task position_task_7001de5f08ae4dabbd3881fed57dcd5a, model qwen/qwen3.5-flash-02-23, provider openrouter, Demo Safe Mode enabled.

3. Reproduction conditions

Any OpenRouter Structured Output root equal to Infinity, -Infinity, NaN, an exponent overflow such as 1e999, or a non-object JSON root reproduced the boundary defect without network access. A nested overflow reproduced the same defect below an object. The exact production FAILED state and original reservation were copied read-only into isolated storage and reproduced the missing one-shot Conclusion recovery path.

4. Root cause

Python's json.loads deliberately accepts non-standard Infinity/NaN constants and converts exponent overflow to a non-finite float unless told otherwise. The OpenRouter Provider returned the decoded value directly to Pydantic and did not enforce the Structured Output response invariant that the root is a JSON object containing only finite JSON numbers. The resulting PayloadValidationError could not preserve the scalar invalid payload, so audit metadata was also insufficient.

Conclusion had a second systemic defect: its Provider task IDs were random and it had neither checkpoint recovery nor a persisted one-shot Provider retry route. Restarting could not distinguish a safe uncalled downstream stage, a saved result awaiting checkpoint restoration, and an ambiguous/billed failed call.

5. Why it happened

The strict schema work validated the request schema but treated Provider response decoding as ordinary Python JSON parsing. Mock always returned dictionaries and therefore could not exercise non-standard JSON tokens. Conclusion predated the deterministic task/reservation/recovery controls already developed for Researcher and Deliberation.

6. Why prior tests did not find it

Existing Provider tests covered malformed envelopes, HTTP status, network interruption, and strict request schemas, but not non-finite JSON constants, exponent overflow, nested non-finite values, or scalar/array roots. Conclusion tests covered normal revision routing and Safe Mode but not a billed contract-invalid response, explicit retry authorization, or result-message persistence surviving a checkpoint write fault.

7. Cycle 015 repair plan and v2 comparison

Plan A: enforce standard object JSON plus recursively finite numbers at the shared OpenRouter response boundary. This follows v2 Systemic Repair and protects all 22 roots.

Plan B: record only response SHA-256, character length, root type, and invalid JSON path. This follows explainable debugging without persisting potentially sensitive response bodies.

Plan C: give all four Conclusion Provider stages deterministic logical task IDs and persistent reservations. This matches v2 Logical Task Identity and Reservation principles.

Plan D: add Conclusion checkpoint recovery and an explicit Demo-Safe one-shot retry authorization. Reuse valid upstream checkpoints and use a separate `_operator_retry_1` task. This matches localized re-execution and cost control.

Plan E: if validated result PMP messages survived a state/checkpoint save fault, restore them by task and dependency identity with Provider calls zero. This matches Persist Before Advance, idempotency, and Recovery R9.

Plan F: Static -> targeted Unit -> full Unit -> Integration -> full Mock E2E -> exact production-state isolated Mock recovery -> one localized Real retry. This is the v2 validation ladder and avoids a full restart.

- OpenRouter now rejects Infinity, -Infinity, NaN, exponent overflow, nested non-finite numbers, and non-object roots before Pydantic.
- Added ProviderResponseContractError. It is retryable only by explicit operator action and always disables automatic retry.
- Error PMP records response hash/length/root/path and never the response body.
- Conclusion Position, Evaluation, Integration, and Quality Review task IDs are deterministic by upstream revision, internal revision, and operation variant.
- Conclusion Quality Review input now carries its logical task_id.

- Recovery inspects saved checkpoints, restores correlated saved result PMP messages, preserves completed expensive stages, and calls only the first truly unfinished stage.
- Provider resend requires a persisted pending authorization, creates a distinct retry reservation, consumes authorization once, and rejects retry-of-retry.
- Legacy saved input_value=inf PayloadValidationError is classified on read as ProviderResponseContractError; the production JSON is not rewritten.
- Conclusion Manager RD advanced to 1.0.1 and README documents the boundary and CLI.

10. Design meaning

A strict Structured Output contract has two independent halves: the JSON Schema sent to the Provider and the JSON document accepted back. Pydantic is not the raw JSON grammar boundary. A response that may already have been generated and billed must never be silently replayed under the same logical task. Durable result messages are checkpoints and must be reused before any resend decision.

11. Other-layer impact

The response decoder is shared by Producer, Researcher, Deliberation, Conclusion, and Playwright, so all 22 OpenRouter output roots receive the same finite-object guarantee. Existing Researcher/Deliberation retry authorization semantics remain intact. No Producer, Researcher, Deliberation, Playwright, PMP shape, outbox format, or existing checkpoint JSON was migrated.
