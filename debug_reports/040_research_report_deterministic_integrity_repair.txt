1. What happened

The saved Researcher Quality Review returned three findings. Two were machine-
repairable integrity findings and one was a real evidence coverage gap:

- fqr_limitations_duplication (HARD): Report-level research_limitations repeated
  source-level disclosures verbatim.
- fqr_source_classification_expert_news (HARD):
  source_134a53bf88dcde074747e0a5 was EXPERT even though both expert identity fields
  were null and its saved xtech.nikkei.com context explicitly described reporting.
- fqrq_ai_emp_003_news_missing (EVIDENCE_SUFFICIENCY): rq_ai_emp_003 requires NEWS,
  but no saved NEWS source is linked to that Research Question.

The workflow was BLOCKED although the first two findings did not require new
Retrieval or another LLM review.

2. Why it happened

The Report aggregation collected specialist limitations and source limitations into
the top-level list. Its previous order-preserving dedupe removed repeats inside that
list, but it did not distinguish a global Report limitation from the same disclosure
already owned by a source. The production Report therefore had 54 unique top-level
strings, 40 of which exactly matched the 40 source-level strings.

The xtech source was retrieved successfully and assigned to the Expert Researcher.
ResearchResult correctly enforced the assigned task category, while Cycle 037
provenance hydration correctly refused to invent expert_name or affiliation. Manager
aggregation then enforced the assigned EXPERT type but had no narrow canonical rule
for a recognized media URL plus a saved reporting context. The result was a
mechanically inconsistent EXPERT record with no expert identity.

The target source is linked only to rq_ai_emp_002. It is not linked to
rq_ai_emp_003. Reclassifying it as NEWS therefore must not satisfy the third finding.

3. How it was fixed

- New Report aggregation removes only exact Unicode-equal source-level copies and
  exact repeated Report strings. It preserves first order, source-level disclosures,
  and every non-identical limitation. It performs no semantic merge or rewrite.
- Human Evidence recovery can persist two typed zero-call repair artifacts:
  report_limitation_exact_deduplication and
  recognized_media_source_reclassification.
- The media rule is deliberately narrow: EXPERT, both expert identity fields absent,
  recognized xtech.nikkei.com host, saved reporting/news context, and a valid NEWS
  metadata contract. A domain alone is insufficient.
- EXPERT compatibility remains intact for anonymous or institution-based expert
  material that is not proven to be recognized reporting.
- Classification repair changes only source_type and category-specific metadata.
  source_id, evidence_id, Research Question IDs, URL, title, content, timestamps,
  retrieval provenance, quality assessment, and limitations remain unchanged.
- Coverage, evidence_gaps, unresolved_questions, category references, and category
  counts are recomputed from Research Plan requirements and repaired sources.
- A missing-category finding is resolved only when the repaired source itself has the
  required category and is linked to the same Research Question. An unrelated source
  cannot satisfy it.
- The original revision_required Quality Review and all three original findings are
  preserved. Current status is represented through resolved_integrity_findings and
  the effective Human Evidence Gate view.

4. Design meaning

The repair keeps the Human Evidence Gate boundary intact:

  hard integrity -> deterministic system repair or block
  evidence sufficiency -> explicit Human decision

Category ownership now combines the specialist task contract with a very small,
saved-metadata canonicalization rule. The system does not ask an LLM to reclassify a
source and does not introduce a general media taxonomy. Repair artifacts form an
auditable Evidence Set hash chain, so a later Human Decision is bound to the repaired
Evidence Set rather than silently replacing the pre-repair identity.

5. Same-family audit and prevention

The new aggregation path prevents the limitation duplication in future workflows.
The recognized-media rule runs before assigned-category filtering, so all Researcher
aggregation uses the same rule. Ten fault tests cover exact versus semantic dedupe,
missing expert identity detection, zero-call NEWS repair, identity preservation,
same-question and unrelated-question coverage, Gate eligibility, unresolved Hard
failure, and reservation/call invariants.

The first full verification exposed a separate test-isolation defect: LLM Provider
was forced to mock but PRDCP_RETRIEVAL_PROVIDER could leak from the operator .env and
attempt a real search. Verification and the CLI integration test now force both LLM
and Retrieval providers to mock. This prevents accidental paid/network calls during
regression tests.
